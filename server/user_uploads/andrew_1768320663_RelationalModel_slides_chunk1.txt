### The Relational Data Model

The concept originated from a groundbreaking paper by E.F. Codd in 1970 titled “A relational model of data for large shared data banks.” Key insights from Codd include:
- Separation of physical implementation from logical design.
- Describing data and operations mathematically.

### Introduction to Relational Databases from a Practical Point of View

A sample table to help keep track of bank accounts might look like this:

|----------------|------------|----------|---------|

| 102            | W. Wei     | 2000.00  | checking |
| 103            | J. Smith   | 5000.00  | savings  |

### Size of a Table

- Cardinality: The number of rows in the current instance (e.g., in the example, cardinality is 5).
- Degree or Arity: The number of columns (e.g., the degree of the relation is 4).

### Table Keys

Each table has a key, where the values must be unique. 

A key may consist of one column or more (composite key).

- An ID/number is usually considered a key (if unique)
- Examples of keys: Student ID, Employee ID, SSN, Ticket Number
- A name is generally not a key due to the potential for duplicates.

### Keys

- Deciding which column(s) is a key requires domain knowledge. Engage with domain experts (e.g., application users).
- A table can contain multiple keys. For example, both `Student_id` and `username` can be keys for the student table.
- Among the keys, one is chosen as the primary key.

###

### Connections between Tables

Foreign keys establish a connection between tables. For example, `Deposit.AcctNo` serves as a foreign key that references `Account.Number`. This linkage helps maintain referential integrity within the database.

| Account Number | Owner      | Balance  | Type    |
|----------------|------------|----------|---------|
| 101            | J. Smith   | 1000.00  | checking |
| 102            | W. Wei     | 2000.00  | checking |

| AcctNo | Transaction-id | Date      | Amount   |
|--------|----------------|-----------|----------|
| 102    | 1              | 10/22/00  | 500.00   |
| 102    | 2              | 10/29/00  | 200.00   |

### Foreign Keys

Foreign keys play an essential role in ensuring data integrity across tables by referencing unique identifiers from related tables.
