### The Growth of Functions
- The time required to solve a problem is determined by the following:
  - Number of operations executed
  - Depends on the size of the input
  - Speed of the hardware and software (does not depend on the size of the input)
  - Can be accounted for by constant multiplier
- Big-O notation estimates the growth of functions representing the number of operations executed.

### How to Analyze Algorithms?
- **Comparison of Execution Times:** No
- **Counting the Number of Statements Executed:** No
- **Expressing Running Time as a Function of Input Size (f(n)):** Yes
- Analysis is independent of machine speed, programming style, programming language, etc.

### Complexity of an Algorithm
- The complexity of an algorithm refers to the amount of time and space required to execute the algorithm.
- Computing the amount of time and space used without the actual program requires focusing on essential features that affect performance.

### Example: Finding the Maximum Element
- **Pseudocode for `findMax(s, n)`**
  ```
  currentMax = s1
  k = 2
  while k ≤ n do
      if s[k] > currentMax then
          currentMax = s[k]
      end if
      k = k + 1
  end while
  return(currentMax)
  ```

### Analyzing Algorithm `findMax`
- Time of execution depends on the number of iterations of the while loop which is typically n−1.
- The work done in each iteration is constant, leading to a time complexity proportional to n.

### Example: Nested Loops
- If given a sequence `s1, s2, …, sn`, the number of iterations executed is n^2, and the total time needed is proportional to n^2.

### Big-O Notation
- Estimates the growth of a function without worrying about constant multipliers or smaller order terms.
- Big-O notation analyzes asymptotic performance independent of the implementation, assuming operations take the same time.

### Big-O Definition
- Let f and g be functions from N to R. 
  - f(x) is O(g(x)) if there are constants C and k such that |f(x)| ≤ C|g(x)| for all integers x > k.

### Examples of Big-O
1. **Example 1:** Complexity of an algorithm of at most 60n^2 + 5n + 1 units of time is O(n^2).
2. **Example 2:** Show that n^2 is not O(n).
3. **Example 3:** Show that 10n^3 - 5n^2 + 2560 is O(n^3).

### Theorems
1. Theorem 1: Let f(n) = ak nk + ak−1 nk−1 + … + a1n + a0 be a polynomial in n of degree k, then f(n) is O(n^k).

### Additional Examples
- Analyze loops with various iterations to determine time complexity and tight bounds, e.g., factorial function estimates and nested loop iterations.

### Common Growth Functions
- Constant: O(1)
- Logarithmic: O(log n)
- Linear: O(n)
- Linearithmic: O(n log n)
- Quadratic: O(n^2)
- Exponential: O(c^n)
- Factorial: O(n!)

### Big-Omega and Big-Theta Definitions
- **Big-Omega:** f(x) is Ω(g(x)) if there are constants C > 0 and k such that |f(x)| ≥ C|g(x)| for all integers x > k.
- **Big-Theta:** f(x) is Θ(g(x)) if f(x) is O(g(x)) and f(x) is Ω(g(x)).
