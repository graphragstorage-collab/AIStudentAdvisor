## Introduction to Algorithms
1. **Definition of an Algorithm**
   - A finite sequence of precise instructions for performing a computation or solving a problem.
   - An algorithm is defined on specified inputs, generates an output, and stops after finitely many instructions are executed.

### 

## Properties of an Algorithm
- **Input**: An algorithm has input values from a specified set.
- **Output**: From each set of input values, an algorithm produces output values from a specified set; the output values are called the solution to the problem.
- **Correctness**: The algorithm produces the correct output for all valid inputs.
- **Effectiveness**: The steps of the algorithm can be executed with precision and in a finite amount of time.
- **Finiteness**: The algorithm must terminate after a finite number of steps.
- **Generality**: The algorithm should solve a general class of problems.

###

## How to Express an Algorithm
- **Pseudocode**: An intermediate representation between an English description and an implementation in a specific programming language.

### Example 1: Prime Number Check
```
procedure is_prime(m)
  for k = 2 to sqrt(m) do
    if m mod k == 0 then
      return(false)
    end if
  end for
  return(true)
end is_prime
```

### Example 2: Find Maximum Element
```
procedure findMax(s, n)
  myMax = s1
  k = 2
  while k ≤ n do
    if sk > myMax then
      myMax = sk
    end if
    k = k + 1
  end while
  return(myMax)
end findMax
```

## Searching Algorithms
**1. Searching**
- Given a sequence of n elements and an element x, determine whether element x is present.
- If x is present, return the location; if not, return -1.
- The elements should be represented in an array in non-decreasing order.

### Searching in a Sorted Array
- To determine whether a given element x is in array A:
  - **Linear Search**: Compare x with each element until a match is found or the end is reached.
  - **Binary Search**: Compare x with the middle element. If equal, x is found. If not, search the left or right half.

###

## Linear Search Procedure
``` 
procedure linearSearch(x: integer, a1, a2, …, an: integers)
  k = 1
  while (k ≤ n and x ≠ ak) do
    k = k + 1
  end while
  if k ≤ n then
    location = k
  else
    location = -1
  return location // index or -1 if not found
```

###

## Binary Search
**Searching in a Sorted Array**
- Determine if element x is present in array A. Return the index if x is found or -1 if not found.

### Binary Search Procedure
```
procedure binarySearch(a[1, …, n], x)
  left = 1
  right = n
  while left < right do
    m = ⌊(left + right)/2⌋
    if x > am then
      left = m + 1
    else
      right = m
  end while
  if x = a[left] then
    location = left
  else
    location = -1
  return location
```

### Efficiency Comparison
- **Binary Search**: At most log2(n) iterations for n elements.
- **Linear Search**: Up to n iterations for n elements.
- Generally, binary search is faster for lists exceeding 20 elements.

## Sorting Algorithms
**Objective**: Arrange n elements in non-decreasing order.

### Bubble Sort
- **Basic Operation**: Compare adjacent elements a[j] and a[j+1] and exchange them if necessary.
- Repeatedly swap adjacent entries until sorted.
- Perform multiple passes over data until all elements are sorted.

#### Example of Bubble Sort
- Initial Sequence: 5 1 4 2 8
- Pass 1: 
  - 5 1 → 1 5 → 1 4 → 1 4 → 2 5 → 1 2 4 5 8
- The maximum number of passes occurs when the input array is sorted in reverse order.

### Bubble Sort Procedure
```
procedure Bubblesort(a1, …, an)
  for i := 1 to n - 1 do
    for j := 1 to n - i do
      if aj > aj+1 then
        swap aj and aj+1
```

## Insertion Sort
- **Idea**: Scan the array from left to right.
- The first element of the unsorted portion is placed in the correct position within the sorted portion.

### Insertion Sort Procedure
```
procedure InsertionSort(a1, …, an)
  for j := 2 to n do
    m := aj // take the first element of the unsorted portion
    i := 1
    while aj > ai do // find insert position
      i := i + 1
    for k := 0 to j - i - 1 do // open insert position 
      aj-k := aj-k-1 // move elements
    ai := m // insert m in position i
```

### Worst-Case Comparisons
The number of comparisons done in the worst case is given by the formula:
\[
\sum_{j=1}^{n} j = \frac{n(n+1)}{2}
\]

## Cashier's Algorithm
### Problem Example
Make change for 67 cents using the fewest number of coins. Available denominations:
- Quarters (25 cents)
- Dimes (10 cents)
- Nickels (5 cents)
- Pennies (1 cent)

### Theorem
The Cashier's Algorithm always makes change using the fewest coins possible when change is made using the denominations stated above.
