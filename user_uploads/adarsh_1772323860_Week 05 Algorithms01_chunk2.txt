### Key Topics Covered
1. **Definition and Properties of Algorithms**
   - Finite sequence of precise instructions.
   - Specified inputs and outputs.
   - Correctness, effectiveness, finiteness, and generality.

2. **Pseudocode Notation**
   - Intermediate representation between natural-language description and concrete programming language. 
   - Example procedures:
     - `is_prime(m)` for primality testing.
     - `findMax(s, n)` for locating the maximum element.

3. **Searching Algorithms**
   - **Linear Search**: Sequential comparison of each array element.
     - Complexity: `O(n)`
   - **Binary Search**: Divide-and-conquer on a sorted array.
     - Complexity: `O(log₂ n)`
   - Detailed pseudocode, step-by-step comparison counts, and analysis provided.

4. **Sorting Algorithms**
   - **Bubble Sort** and **Insertion Sort**: 
     - Algorithmic ideas, invariant conditions, pass-by-pass execution discussed.
     - Worst-case comparison counts: `Θ(n²)`.
     - Pseudocode implementations shared.
     - Visualizations referenced from the USFCA Galles comparison-sort site.

5. **Algorithmic Analysis**
   - Discussion on efficiency, number of iterations, work per iteration, and thresholds where binary search outperforms linear search (typically > 20 elements).

6. **Cashier’s Algorithm**
   - A greedy method for making change with U.S. coin denominations (quarters, dimes, nickels, pennies).
   - Theorem stating optimality for these denominations with proof sketch.

### Growth of Functions
- The time required to solve a problem is determined by:
  - Number of operations executed.
  - Depends on the size of the input.
  - Speed of the hardware and software does not depend on input size.

### Complexity of an Algorithm
- The complexity refers to the amount of time and space required to execute the algorithm.
- Essential features affecting performance need to be focused on to compute time and space without the actual program.

### Example: Maximum Element in a Sequence
- **Pseudocode**:
  ```pseudocode
  procedure findMax(s, n)
      currentMax = s[1]
      k = 2
      while k <= n do
          if s[k] > currentMax then
              currentMax = s[k]
          end if
          k = k + 1
      end while
      return(currentMax)
  end findMax
  ```
- Time of execution depends on the number of iterations of the while loop. Performance does not generally depend on the values of the elements.

### Growth of Functions and Big-O Notation
- Week 6.1 covers Big-O notation and common growth functions.
- Big-O notation estimates the growth of functions without worrying about constant multipliers or smaller order terms.
- Performance analysis assumes different operations take the same time for estimation.

### Big-O Definition
- Let f and g be functions from N to R. 
  - f(x) is O(g(x)) if there are constants C and k such that |f(x)| ≤ C|g(x)| for all integers x > k.

### Examples of Big-O
1. Show that an algorithm terminating at 60n² + 5n + 1 units of time is O(n²).
2. Show n² is not O(n).
3. Show 10n³ - 5n² + 2560 is O(n³).
4. Algorithm with time 6n² + 5n log(n) shows complexity of O(n³).
